## 第1回・2コマの方針

- ユーザー提供の2026年度前期Python第1回・第2回PDFを参考に、明日の2コマをJava向けに構成する。PDFそのものは公開しない。
- 1コマ目は実行方法、Hello World、整数・小数・文字列の表示、`print` / `println`、型付きの変数を扱う。
  - 自力課題は好きな文字列、変数を使う自己紹介、山形模様。
- 2コマ目は数値の演算、整数の割り算と余り、文字列の連結・繰り返し、変換、代入、面積計算を扱う。
  - 自力課題は文字列の繰り返し、三角形・円の面積。時間換算は発展課題。
- クラスと `main` は基本の形として使い、詳しい仕組みは後の回で扱う。
- シラバスの第2週「演算子と変数」の基本を1コマ目・2コマ目に先行して導入する。第2週は復習と応用に使う。
- JavaとPythonで意味が異なる `//`、`**`、文字列の `*` をそのまま移さない。
- 別科目で同時進行のC言語（`../keisanki2026`）とも、該当コードの近くで1行程度比較する。C教材で扱った範囲だけに触れる。
  - 学生の例はC教材の課題2と同じ「出席番号 99 番の 太田健吾 です。」。身長など個人に関わる数値は使わない。
- 1つの見本で新しい考え方を1〜2個に絞り、小さな見本に分ける（2026年9月29日に改訂）。
  - エラーの体験は、誤りを含むコードを入力欄に入れておき、学生が直す形にする。
  - 1コマ目は見本6つと直す演習4つ、2コマ目は見本9つと直す演習4つ。発展課題は両コマに入力欄を置く。
  - 余裕がある人向けの内容は「発展課題（余裕がある人のみ）」節にまとめる。2コマ目の `parseInt` の見本は課題で使わないため、発展1に置く。
  - 見本を書き換える確認の下には試す欄を置き、写経したコードと試したコードの両方を提出物に残す。
- TeaVM実行環境は、両コマの掲載コードをブラウザで検証する。演習室の端末での動作確認は残る。

## 実行環境に必要な機能

| 区分 | 必要な機能・確認事項 |
| --- | --- |
| 第1回から必要 | `Main.java` のコンパイルと実行、日本語の出力、printとprintln、コンパイルエラーの表示 |
| 後期の範囲から必要 | 数値・文字列、分岐、ループ、配列、メソッド、クラスとオブジェクト |
| 運用上必要 | 無限ループの停止、停止後の再実行、入力コードの復元、結果を含む提出HTML保存 |
| 採用前に検証 | 標準入力、実行時エラー、連続実行、演習室での一斉利用 |
| 教材設計により判断 | Scannerの導入時期、実行途中の入力、複数ファイルへの分割 |

- 後期のシラバスにはScanner、GUI、複数ファイルの指定はない。
  - これらを必修範囲と推測しない。クラスの導入は1ファイルでも作成可能。
  - ただし標準入力が使えるかは、後の演習の選択肢に関わるため採用前に確認する。
