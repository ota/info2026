## 編集・表記

- 原稿は `content/lessonXX.md`。生成済みHTMLを直接編集しない。
- ユーザーがZedまたはブラウザで行った編集を尊重し、変更前に現状と差分を確認する。
- 初学者向けに短い文と階層のある箇条書きを使う。
- 句点「。」の後は、表示時に自動で改行する（`scripts/generate.mjs` の `sentence_breaks`）。原稿で文ごとに改行や空行を入れなくてよい。
  - 「。」の直後が閉じかっこの場合と、文末では改行しない。コード（`` ` ``）の中は対象外。
- 専門語を説明なしで導入しない。意味のあるカギカッコを削らない。
- 自明な小見出し、英語の飾り文句、宣伝的なタイトルを増やさない。
- 説明と注意は該当コードの近くへ置く。誤記例は正しいコードと区別する。
- 見本コードはCanvas表示、学生の入力欄は貼り付け禁止。教員の編集欄は貼り付け可能。
- エラーを直す演習は `:::exercise ID Main.java fix` と書く。誤りのあるコードを入力欄に最初から入れ、Canvasには描かない。
  - この欄だけに「最初のコードに戻す」ボタンがある。2回押すと戻り、自動保存も更新する。
- 確認で見本を書き換えさせるときは `:::check 見本のID` と書く。確認の下に試す欄（ID は `見本のID-try`、2つ目以降は `-try2`…）が付く。
  - 「上のコードをコピー」で、学生が見本の欄に打ち込んだコードを写す。写経した欄は書き換えさせない。
  - 見本を書き換えない確認は、IDなしの `:::check`。
  - 確認では、やること（操作と確かめること）の文を `**…**` で太字にする。注意書きや説明は太字にしない。
- 余裕がある人向けの内容は、演習問題の後の「発展課題（余裕がある人のみ）」節（`{#extension}`）に置き、小見出しは `### 発展1　…`。本文の途中に「余裕があれば」を置かない。
- 保存欄に達成状況（達成率・メッセージ・内訳・まだの欄）を出す（`src/progress.js`）。発展課題は達成率に入れず別に数える。
  - 見本：見本と同じ（字下げ・行末の空白・空行は無視）で、エラーなく実行。エラーを直す：最初のコードから変えて実行。確認の試す欄：コピー元から書き換えて実行。課題：実行できればよい。
  - `:::expected` は直前の見本の正解になる。出力が決まっている課題などは `:::expected 課題のID` と書き、出力の一致も条件にする。
  - 達成した欄には実行後に「✅ 合格」を出す。記録はこの端末のlocalStorage（`…:run`）。提出HTMLにも達成状況を含めるが、目安であり改ざん検証能力はない。
- 見本の欄の「見本と比べる」は、行の対応を取ってから、違う行と最初に違う文字に色を付ける。
- 学生の入力欄は、透明なtextareaの下に色付きの `pre` を重ねて色分けする。両者のフォント・行の高さ・余白・タブ幅をそろえる。

## 実行環境と公開

- 第1回用のTeaVM + teavm-javacを接続済み。起動・制約・検証は `notes/Java実行環境の構築.md` を参照。
- 第1回の公開先は `https://ota.github.io/info2026/lesson01-1.html` と `https://ota.github.io/info2026/lesson01-2.html`。旧 `lesson01.html` は1コマ目の別名。リポジトリは `ota/info2026`。
- 公開更新は `.github/workflows/deploy.yml` の手動実行。pushだけではデプロイされない。
- `public/teavm/` のライセンス文書と対応ソースを、実行用ファイルと一緒に配布する。
- 2コマ目ではユーザーの追加依頼により、演算子・変数・文字列連結・面積計算の導入も扱う。掲載する全Javaコードをブラウザ実行環境で検証する。
- CheerpJを学校利用で無条件に無料とみなさない。採用・公開前に条件を確認する。
- ライセンス問い合わせなどの第三者への連絡は、明示的な依頼なしに行わない。
- 2026年9月29日にGitHub作成・Pages公開の依頼を受領。以後の公開更新はユーザーの依頼に沿って行う。
- 提出HTMLや端末情報には改ざん検証能力がない。本人確認の証拠と説明しない。
